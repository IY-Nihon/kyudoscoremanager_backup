# kyudoscoremanager_backup

弓道部の記録アプリ「弓道部的中ノート」（[kyudoscoremanager_app](https://github.com/IY-Nihon/kyudoscoremanager_app)）の、本番データを毎日バックアップする仕組みのコードです。

実際に毎日動かしているのは、このコードを置いた**非公開のリポジトリ**です。実行の記録・ログ・暗号化したバックアップ・鍵は、すべてそちらにあり、ここには置いていません。ここは仕組みを読んでもらうための公開の写しです。

## 何をしているか

- 毎日深夜 0 時（日本時間）に GitHub Actions が動く
- Firebase Admin SDK で、Firestore・Realtime Database の全データと、Firebase Auth の利用者の一覧（uid・メール・作った日時・最後のログイン日時だけ。パスワードのハッシュは取らない）を取る
  - Firestore は根の集まりから下の集まりまで全部たどる。中身は 100 件ずつまとめて読み、同時に走らせる問い合わせは 8 本まで
  - `disposable_domains`（使い捨てメールのドメインの一覧。約 1 万件）だけは控えず、件数だけを残す。公開の一覧から入れ直せる（アプリの `npm run ops:disposable:run`）うえ、毎日読むと無料の読みの枠の半分ほどを使うため
- 取った直後に、本番のデータと **1 文字単位で突き合わせる**（`scripts/verify-exact.mjs`）。違いがあれば失敗として知らせる
  - 控えにある集まりは全部見る。中身まで比べるのは、下の 3 つのほかの全部（団体の帳面・団体の文書・記録・名簿・所属の証・個人 ID の逆引き表・同意など）
  - 件数だけ比べるもの: 消した団体の 30 日の控え（`deleted_accounts`）・不具合の便り（`errorReports`）・回数の控え（`rate_limits`）
  - 控えに無い集まり（控えたあとにできた・取りこぼした）も探して知らせる
- gzip で縮め、**AES256 で暗号化してから**成果物（Artifacts）として保存する。鍵が無いと止まり、素のままでは上げない。暗号化したら、その場で戻して元と同じかを確かめてから素のファイルを消す

## 置いてあるもの

| ファイル | 中身 |
|---|---|
| `scripts/backup-firestore.mjs` | 全データを取り、1 つの JSON（`{ exportedAt, projectId, format, firestore, skippedCollections, rtdb, auth }`）にして縮める |
| `scripts/verify-exact.mjs` | 取った控えと本番を突き合わせる。日時型・参照・位置・バイト列・入れ子の配列もそろえて比べる |
| `package.json`・`package-lock.json` | 使う部品（firebase-admin）の版と中身の印を固定する |
| `workflow/backup.yml` | 実際に使っているワークフローの写し（ここでは動かないよう `.github` の外に置いている） |

非公開のリポジトリへは、`scripts/`・`package.json`・`package-lock.json` をそのまま、`workflow/backup.yml` を `.github/workflows/backup.yml` として写す。

## 守りのために決めていること

- **素のデータを、人の目に触れる場所に置かない。** 中身には部員の氏名や記録、利用者のメールアドレスが入るので、必ず暗号化してから保存する。暗号化の鍵が設定されていなければ、その日の控えを作らずに止まる（控えが 1 日できないことより、素のまま出すことのほうが重いと考えている）
- **ログに個人や団体が分かるものを出さない。** 団体 ID・団体名・人の名前・文書の ID と中身・メールアドレス・uid・ライブの枝は出さず、集まりの道の型（`groups/*/sessions`）ごとの件数と項目の名前だけを出す。違いが見つかったときも、「何番目の団体の、どの項目か」で知らせる。エラーの文に入る文書の道も伏せる
- **鍵はコードに書かない。** Firebase のサービスアカウント鍵と暗号化の合言葉は GitHub Secrets に置く。合言葉は gpg へ標準入力で渡し、コマンドの行に載せない
- **部品を勝手に差し替えさせない。** 部品は `package-lock.json` の版と中身の印のとおりに入れ（`npm ci`）、install の台本は走らせない（`--ignore-scripts`）。この後でサービスアカウントの鍵を渡すため
- **外から書き換えさせない。** ワークフローの権限は読み取りだけ（`contents: read`）で、GitHub のトークンも手元に残さない。外部からの Pull Request ではワークフローを動かさない
- **実行の記録も公開しない。** 公開リポジトリでは Actions のログや成果物の一覧を誰でも見られるため、動かすリポジトリを非公開に分けた（2026-11）

## 無料の枠

Firebase は無料版（Spark）、GitHub も無料の枠で動かしている。

- **Firestore の読み（1 日 5 万回。アプリと分け合う）**: 控えは文書 1 件につきおおよそ 3 回（一覧・中身・下の集まりの問い合わせ）、照合はおおよそ 1 回（件数だけのものは 1,000 件で 1 回）。それぞれの読んだ数をログの終わりに出す。枠を使い切ると、その日はアプリも読めなくなる（太平洋時間の 0 時に戻る）
- **成果物の置き場（GitHub Free は 500MB。Packages と分け合う）**: 非公開のリポジトリの成果物はここを使い、いっぱいになると新しい控えを上げられなくなる。ログの「90 日分でおおよそ」で見る
- **Actions の時間（GitHub Free は月 2,000 分）**: 1 回数分

## 復元のしかた（概要）

1. 非公開のリポジトリの Actions から、その日の成果物を取り寄せる
2. 暗号化の合言葉で復号する（`gpg --decrypt`）
3. 展開した JSON から、必要な集まりを Firestore・Realtime Database へ戻す

控えの形（`format: 2`）:

- 文書は `{ id, _fields, _collections: { 下の集まり: [文書…] } }`
- 日時（Timestamp）は ISO 8601 の字（ミリ秒まで）。参照は `{ _ref: 道 }`・位置は `{ _geo: [緯度, 経度] }`・バイト列は `{ _bytes: base64 }`・ベクトルは `{ _vector: [...] }`
- 中身が無く、下に集まりだけがある文書は `_exists: false`（戻すときは文書を作らず、下の集まりだけを戻す）
- 控えなかった集まりは `skippedCollections` に件数とわけを残す（`disposable_domains` はアプリの台本で入れ直す）

鍵を失うと、どの控えも戻せません。鍵はリポジトリとは別の場所に控えています。

## 使っているもの

Node.js 24 / firebase-admin 14 / GitHub Actions / gpg（AES256）
